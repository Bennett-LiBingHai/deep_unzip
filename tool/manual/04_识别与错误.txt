# 第十章 密码库

## 10.1 密码库的作用

加密压缩包每解开一次就要输入一次密码，如果有几十个包用的是同一个密码，逐个输入
是不现实的。密码库用来保存常用的密码，遇到加密包时自动逐个尝试。

密码库保存的是**候选密码**，不是「哪个包对应哪个密码」的映射 —— 本软件不打乱这个
关系，只是把您给的密码依次往上试。

## 10.2 添加与删除密码

密码库页面顶部有两块内容：上面一张统计卡，显示「已保存密码」的条数与「累计命中」
的总次数；下面一行是输入框和「添加」按钮。

添加：在输入框里输入密码，点击「添加」，或直接在输入框里按回车。

删除：每条密码右侧有一个红色的删除按钮，点击后弹出确认卡片，确认即删除。

同一个密码不能重复添加。已经存在的密码再添加一次不会产生第二条记录。

## 10.3 每条记录显示什么

| 字段 | 含义 |
| 密码 | 密码原文，等宽字体显示 |
| 匹配 N 次 | 这个密码成功解开过多少个包 |
| 最近: 时间 | 最后一次命中是什么时候 |

命中次数不是装饰：它是候选顺序的依据之一，见 10.5 节。

## 10.4 自动尝试

解压时如果遇到加密包，本软件会**自动**用密码库里的候选密码逐个尝试，无论
「无法解密时弹窗」这颗开关是开还是关。

这里要澄清一个常见误解：那颗开关**不决定要不要自动试密码**，它决定的是**试完
之后问不问**。关掉它，密码库照样会先试一遍；区别只在于试不出来时是弹窗询问，
还是直接跳过这个包并记一条日志。

## 10.5 尝试顺序

候选密码不是按添加顺序排的，而是按以下优先级排序：

| 优先级 | 依据 |
| 一 | 这个目录上一次成功用过的那个密码 |
| 二 | 命中次数多的在前 |
| 三 | 最近使用过的在前 |
| 四 | 添加顺序 |

第一优先级是最有用的一条：同一批备份切出来的包通常用同一个密码，上一次在同一个
目录里试成功过的密码，很大概率这次也对。常见情况下第一条就命中，不需要试完整个
密码库。

排序只影响**尝试的视图**，不修改密码库页面上的顺序 —— 否则您的密码列表会随着
使用不断跳动。

## 10.6 密码库为空时

如果密码库是空的，而当前这个包需要密码，本软件不会弹出一个「试了 0 个密码」的
选择界面，而是直接给出错误提示，说明需要密码但密码库为空，并提供手动输入的入口。

## 10.7 手动输入密码

自动尝试没有成功时，会弹出密码弹窗。弹窗上显示这个包的文件名，以及一行说明：
密码库里试过几个密码、都没通过。弹窗下方有一颗「手动输入密码」按钮。

点击后进入输入界面，输入框的提示文字是「输入这个压缩包的密码」，右侧有一个眼睛
图标，可以切换明文与圆点显示。输入完成点击「验证」。

验证的结果有三种：

- 通过：本软件继续解压，并把该密码记为该目录的最近成功密码。
- 未通过：显示提示，可以重试。
- 分不清：见 10.9 节。

「手输密码存入密码库」开关打开时（默认打开），手动输入且验证通过的密码会自动
存进密码库，供以后自动尝试使用。关掉它，手输的密码就只用于这一次。

## 10.8 密码保存在哪里

密码保存在系统提供的加密存储中 —— Android 的密钥库为它生成并保管密钥，落盘的
是密文，不是明文。本软件不会把密码写进普通的配置文件中。

同样地，**密码不会被写进日志**。日志里只记录「这个包是用密码库里的密码解开的」
或者「是用手动输入的密码解开的」，不记录密码本身。日志文件是明文的，密码跟它
走一趟就绕过了上面那道防线。

> 密码库随应用一起卸载。卸载前请确认没有还需要用到的密码。

## 10.9 一种诚实的说法：分不清

对于某些加密方式，**根本无从判断**是密码给错了，还是加密数据本身坏了。

七种压缩格式里的七-Zip 内容加密就是这类：它没有校验字，密码错了会解出噪声，
一直漏到解压算法的深处才炸，而此时错误信息与「数据损坏」是同一个。RAR3 的
加密也属于这一类。

遇到这种情况，弹窗上不会写「密码错误，请重试」这样替用户下结论的话，而是写：

> 验证未通过：可能密码错误，也可能文件已损坏。

日志里对应的标记也不是「密码未匹配」，而是「密码或损坏」。

相对地，ZIP 的 AES 加密、RAR5 的加密是有校验字的，能确定是不是密码的问题，
这两种情况下仍然照常提示「密码错误」。

# 第十一章 格式识别与伪后缀

## 11.1 按文件头识别

本软件判断一个文件是什么格式，**不看后缀名**，而是读文件开头的若干字节，与已知
格式的特征值比对。这些特征值叫魔术字节。

| 格式 | 特征值 | 位置 |
| ZIP | 50 4B 03 04 | 开头 |
| RAR4 | 52 61 72 21 1A 07 00 | 开头 |
| RAR5 | 52 61 72 21 1A 07 01 00 | 开头 |
| 7-Zip | 37 7A BC AF 27 1C | 开头 |
| GZIP | 1F 8B | 开头 |
| TAR | ustar | 偏移 257 |
| ISO | CD001 | 偏移 0x8000 |

完整的清单见第十七章。

因为判断依据是文件内容，把一个 ZIP 改名成 `报告.pdf` 之后，本软件仍然能认出它是
ZIP，并在扫描结果里列出它，角标显示「伪后缀」。

## 11.2 自解压文件

以 MZ 开头的文件是 Windows 可执行文件。有一类自解压压缩包（SFX）就是把压缩包
和一段解压用的小程序粘在一起，这类文件的后面藏着一个真正的压缩包。

本软件在前一兆字节的范围内重新搜索格式特征值，找到之后按找到的位置作为起点解开。

## 11.3 前置数据后面追加的压缩包

还有一类更常见的分享包：前面是一张完整能打开的图片（或别的普通文件），压缩包
**整段粘贴在后面**。纯图片目录里出现一个几十兆的「png」，往往就是这种。

它的麻烦在于：开头的特征值是图片的，末尾的 ZIP 目录索引也没有（如果追加的是
RAR 或 7-Zip），从任何一头看都不像压缩包。

本软件的做法是：在文件开头的一段范围内**向前搜索** RAR 与 7-Zip 的特征值，
找到候选之后，再按各自的规则**校验紧随其后的块头**。只有块头校验通过才算数 ——
一段随机数据里凑巧出现几个特征值字节是常有的事，校验就是用来排除它们的。

在校验通过的位置上，本软件按该位置作为起点解开，并在伪后缀弹窗的「处理方式」
里注明「跳过 N 字节前置数据」。

搜索的范围由「设置」页「智能识别」一组的「前置数据搜索窗口」决定，默认 1 MB，
可填 256 KB 至 8 MB。调大能认出封面更长的包，代价是每个认不出来的文件多读
这么多字节。

需要说明的是，这一项**只影响这条搜索**。上一条讲的自解压文件（MZ 开头）走的是
另一条固定的路，不读这个设置 —— 所以把窗口调到多小，原本认得出来的东西也不会
因此变得认不出来，减少的只是这条搜索的覆盖面。

追加的若是 ZIP，走的是 11.7 节讲的「读文件末尾」那条路，不在这里重复搜。

## 11.4 伪后缀处理弹窗

「设置」页「智能识别」一组里有一颗「伪后缀时暂停」开关，默认打开。开关打开时，
一旦检测到后缀与真实格式不符，解压过程中会弹出提示卡片：

| 字段 | 内容 |
| 声明后缀 | 文件名的后缀，红色显示 |
| 文件头 | 实际读到的特征值，十六进制 |
| 真实格式 | 按特征值判断出来的格式 |
| 处理方式 | 将要采取的动作，例如「按 ZIP 格式解压」 |

弹窗上还有一行十六进制预览，显示文件开头的若干个字节，便于人工核对。

两颗按钮是「取消」与「确认解压」。取消等于跳过这个包；用手势滑掉弹窗，等同于
取消。

## 11.5 关掉这颗开关会怎样

关掉「伪后缀时暂停」之后，本软件不再询问，直接按识别出来的真实格式解压。

需要强调的是：**识别本身一直在做**。这颗开关控制的只是「问不问」，不是「认不认」。
即便关掉它，扫描结果里照样会给伪后缀的文件挂上「伪后缀」角标。

## 11.6 认不出来的时候

如果多种特征值都对不上，本软件会按一组固定的顺序依次尝试按各种格式打开这个文件，
只列条目、不写数据、带超时。这个过程叫级联探测。

级联的顺序大致是：先带着偏移量重试，再按 ZIP、TAR、GZIP、7-Zip、RAR 的顺序
逐个试探。全部失败时给出「无法识别或被篡改」的提示，并说明已经尝试过几种方式。

# 第十二章 分卷压缩包

## 12.1 四种分卷家族

分卷是把一个大文件切成若干片存放，使用时需要把所有片拼起来。不同工具的分卷命名
规则不同，本软件支持四种：

| 家族 | 形态 | 首卷 |
| 裸字节切分 | x.zip.001、x.zip.002 … | x.zip.001 |
| Info-ZIP 跨卷 | x.z01、x.z02 … 加 x.zip | x.zip（排在最后） |
| RAR3 分卷 | x.rar 加 x.r00、x.r01 … | x.rar |
| RAR5 分卷 | x.part1.rar、x.part2.rar … | x.part1.rar |

裸字节切分这一族对**任何**格式都成立，因为它的判据只是「文件名后面跟一个数字
后缀」，与内容无关。常见的还有 `x.7z.001`、`x.tar.gz.001`、`x.bin.001`。

## 12.2 扫描时如何分组

扫描时，本软件会把同一族的多个文件合并成**一个**扫描结果行，行上显示「分片」
角标，展开后可以看到它由几片组成。

分组时会做两项检查：

- **连续性**：序号必须从首卷开始严格递增、没有缺号也没有重复。缺片的组不会被
  当成一个完整的分卷包。
- **首卷格式**：首卷的开头必须是可识别的压缩包特征值。如果 `x.zip.001` 的开头
  根本不是 `PK`，这一组会被否决，各片按普通文件处理。

## 12.3 记录在日志里的形态

成功解开的分卷包，日志上的标记会写成「分片 ×5」这样的形式，即这个包由五片组成。

## 12.4 一片都不能少

解压分卷包时，所有片都必须在。少一片，本软件会如实报错，不会试图解出「部分
结果」—— 那样得到的是一份看起来完整、实际残缺的数据，比直接失败更危险。

因此，**不要用手工的方式移动、重命名或删除分卷中的某一片**。如果需要只取其中
一部分，请先完整解开，再从解出来的内容里取。

## 12.5 已知缺口

Info-ZIP 跨卷这一族（`x.z01` 加 `x.zip`）能被识别、能被正确分组，但它究竟能否
成功解开，尚未经过完整验证 —— 构造真实样本需要特定的打包工具，开发环境里没能
造出合规的样本。因此在「支持的格式」清单里，这一族的说明标注为「未验证」。

其余三种分卷家族都已在真机上验证通过。

# 第十三章 错误处理

## 13.1 两类需要用户决定的情况

解压过程中会在两类情况下停下来问用户：

一、**解压失败**。压缩包损坏、密码不对、数据校验不通过等。

二、**被规则拦下**。压缩包的规模超过了设定的上限，或者目标卷装不下。

两种情况共用同一张弹窗，因为两个按钮的含义完全一样。

## 13.2 弹窗上的两个按钮

| 按钮 | 含义 | 后果 |
| 停止 | 这个包不要了，这一批也不要了 | 队列里剩下的全部丢弃 |
| 跳过 | 这个包不要了，接着解下一个 | 本批继续 |

弹窗上方显示这个包的文件名与失败原因。原因是一句完整的话，说明发生了什么，例如
「解压后共 12 GB，超过上限 8 GB，已放弃」。

> 「跳过」是从前的「继续」改名而来。原来的名字会让人以为「再试一次说不定就好
> 了」，而它其实从来不是重试，而是放掉这个包。改名之后语义就清楚了。

如果用手势把弹窗滑掉，效果等同于「停止」。默认取更保守的那一边，是因为手滑关掉
弹窗不该让程序替用户做一个不可逆的决定。

## 13.3 关掉「错误时暂停」会怎样

「设置」页「错误处理」一组里的「错误时暂停」开关（默认打开）控制着上面的行为。
关掉它之后，遇到问题时不再弹窗，而是自动决断并继续：

| 情况 | 自动处理 | 日志状态 | 日志标记 |
| 压缩包损坏 | 放弃这个包 | 失败 | 解压失败 |
| 格式不支持 | 放弃这个包 | 跳过 | 对应的原因 |
| 密码试尽 | 放弃这个包 | 失败 | 密码未匹配或密码或损坏 |
| 超过限额 | 放弃这个包 | 失败 | 炸弹防护或空间不足 |
| 权限被拒 | **仍然弹窗** | — | — |

最后一行是唯一有例外的：权限问题如果不问用户，会陷入「每个包都失败、每个包都
再试一次」的循环。所以权限相关的错误始终弹窗。

关掉这颗开关适合的场景是「一批包里我知道有几个是坏的，不想每次都停下来问」。
代价是这几个包会直接在日志里变成红色，不会给您选择的机会。

## 13.4 错误原因的分类

失败原因在日志里分为几类，各自有独立的标记，便于事后区分：

- **解压失败**：压缩包本身的问题，比如数据损坏、校验不通过。
- **密码未匹配**：确定是密码不对（有校验字的加密格式）。
- **密码或损坏**：分不清是密码错还是数据坏（无校验字的加密格式）。
- **炸弹防护**：规模超过设定的上限，是本软件主动放弃的。
- **空间不足**：目标卷剩余空间不够。
- **扫描失败**：整个扫描流程没能跑起来。

区分的意义在于，这几种情况的应对方式完全不同：密码问题可以去密码库里补一条，
限额问题可以去设置里放宽，而损坏的包只能换一份。

## 13.5 部分成功的情况

一个压缩包里有个别条目解不出来，但大部分条目正常时，本软件会尽量解出能解的部分，
日志状态记为「部分」，并给出对应的标记。这比整个包放弃更有用 —— 至少能拿到
大部分数据。

## 13.6 安全规则导致的跳过

有一类「跳过」不是错误，而是本软件主动拒绝，状态记为「跳过」而不是「失败」，
用橙色而不是红色显示：

- **自引用**：一个压缩包里装着它自己。继续解下去会无限循环，本软件识别出这种
  情况后跳过。
- **超过深度上限**：嵌套层数超过了设定的递归深度。
- **用户取消**：在伪后缀弹窗上选择了取消。

把「跳过」与「失败」分开，是因为用户看到一排红字会以为程序坏了，而这些其实都是
按规则拦下来的正常行为。

## 13.7 个别条目解不出来时

一个压缩包里有几十个条目，其中一两个解不出来，剩下的大部分是好的。这种情况
本软件会把能解的解开，状态记为「部分」，而不是整个包放弃。

判断的标准是：**已经写出的条目是完整的**。条目级的错误不会污染同包里其它条目
的数据，所以留下大部分结果是安全的。

代价是状态为「部分」的那一条记录需要您自己判断：解出来的东西够不够用。如果那
两个失败条目正是您要的，就换一份包重新下载。

## 13.8 权限相关的问题

权限问题是唯一在关掉「错误时暂停」之后**仍然弹窗**的一类。原因很实际：如果权限
被拒绝而软件自动跳过每个包，就会变成「每个包都失败、每个包都再试一次」的循环，
日志里刷满一整屏，用户却不知道为什么。

所以遇到权限问题时，弹窗上的文字会直接说明是权限的问题，并给出重新授权的入口。

## 13.9 一次失败的完整记录

把前面几节的碎片拼起来，日志页上一条失败的记录是这样的：

| 部分 | 内容 |
| 标题 | 压缩包的文件名 |
| 状态 | 失败 |
| 大小 | 压缩包自身的体积 |
| 耗时 | 处理用了多久 |
| 标记 | 一到两个说明原因的标签 |
| 说明 | 一句话的失败原因 |

有了「标记」与「说明」两栏，多数情况下不需要再回到原始文件就能判断该怎么办。
代价是日志里不记完整路径与密码 —— 这是 15.5 节解释过的取舍。

## 11.7 判断的先后顺序

收到一个文件时，本软件按固定的顺序做判断。顺序是有讲究的，因为它决定了边界
情形落在哪一档：

一、**先看后缀是否属于容器格式**。属于的，先记为「可能是容器」，但不下结论。

二、**再读文件头，比对特征值**。这一步给出真实格式，与后缀无关。

三、**如果真实格式是 ZIP 家族**，再去看它的中心目录里有没有容器标记。有标记的
确认是容器格式，跳过；没有标记的按压缩包处理。

四、**开头认不出时**，才去看文件末尾（ZIP 的目录索引）与几个固定偏移（磁盘映像
的卷描述符）。

五、**都认不出时**，才在「前置数据搜索窗口」的范围内向前搜 RAR 与 7-Zip 的
特征值并校验块头 —— 这一步最贵，所以排在最后。

六、**真实格式认不出来时**，才进入级联探测。

先后顺序带来的一个可见结果是：一个后缀为 `.docx`、内容确实是 Word 文档的文件
被跳过，而一个后缀为 `.docx`、内容是普通 ZIP 的文件会被当作压缩包列出 —— 判据
始终是内容，后缀只是加速判断的线索。

## 11.8 什么时候要读文件末尾

多数格式的特征值都在文件开头，读几百个字节就够。有两种情况需要读到文件末尾：

一、**没有开头特征值、但可能是 ZIP**。ZIP 的目录索引在文件末尾，从后往前找
「中央目录结束记录」可以反推出这个 ZIP 从哪里开始。自解压文件正是靠这一步找到
藏在可执行文件后面的那个 ZIP。

二、**虚拟磁盘格式**。少数格式的特征值在末尾，读开头认不出来。

读末尾这一步是**惰性**的：只有前面几步都没得出结论才会做。绝大多数文件在读完
开头几百字节之后就已经有结论了。11.3 节讲的「向前搜索」也一样惰性，而且排在
更后面。
