# 第十七章 支持的格式

## 17.1 识别与解压是两件事

「支持一种格式」在本软件里包含两件事：扫描时能否认出来，以及引擎能否打开它。
扫描靠的是文件头的特征值，引擎则一律使用内置的解码核心，不调用任何外部命令，
也不依赖设备上是否装了别的解压程序。

本软件一共识别并支持三十二种格式。

## 17.2 格式与识别依据

| 格式 | 识别依据 |
| ZIP | 文件头 50 4B 03 04；空归档与跨卷标记 50 4B 05 06、50 4B 07 08 |
| RAR | 文件头 52 61 72 21 1A 07 00；RAR5 在末尾多一个字节 01 00 |
| 7-Zip | 文件头 37 7A BC AF 27 1C |
| TAR | 偏移 257 处出现 ustar |
| CAB | 文件头 4D 53 43 46，即 MSCF |
| LHA | 偏移 2 起为 -lh，例如 -lh5- |
| ARJ | 文件头 60 EA |
| CPIO | 文件头 070707 或 070701，或二进制变体 C7 71 |
| GZIP | 文件头 1F 8B |
| BZIP2 | 文件头 42 5A 68，即 BZh |
| XZ | 文件头 FD 37 7A 58 5A 00 |
| ZSTD | 文件头 28 B5 2F FD |
| Unix compress | 文件头 1F 9D |
| PPMd | 文件头 8F AF AC 84 |
| MS 压缩 SZDD | 文件头 53 5A 44 44 88 F0 27 33 41 |
| RPM | 文件头 ED AB EE DB |
| AR / DEB | 文件头 !<arch> 后跟一个换行 |
| XAR | 文件头 78 61 72 21 00 |
| CHM / LIT | 文件头 ITSF，或 ITOLITLS |
| WIM | 文件头 4D 53 57 49 4D 00 00 00 |
| ISO | 偏移 0x8000 处 01 43 44 30 30 31 |
| UDF | 偏移 0x8000 处 00 42 45 41 30 31 01 00 |
| DMG | 文件末尾 512 字节的页脚以 6B 6F 6C 79 开头 |
| SquashFS | 文件头为 hsqs、sqsh、shsq、qshs 之一 |
| CramFS | 偏移 16 处出现 Compressed ROMFS |
| QCOW | 文件头 51 46 49 FB 00 00 00 |
| VDI | 偏移 0x40 处出现 7F 10 DA BE |
| VMDK | 文件头 4B 44 4D 56，即 KDMV |
| VHD | 文件头 conectix；固定大小的 VHD 不识别 |
| VHDX | 文件头 76 68 64 78 66 69 6C 65 |
| Android Sparse | 文件头 3A FF 26 ED 01 00 |
| NTFS 卷 | 偏移 3 处出现 NTFS 加四个空格 |

## 17.3 分卷命名

任何格式都支持裸字节切分，也就是在文件名后面追加数字后缀，例如 `x.001`、
`x.bin.001`、`x.zip.001`。这一族的判据与内容无关，所以不逐一列出。

只有**格式特有**的分卷命名需要单独说明：

| 家族 | 命名 | 首卷 |
| RAR5 | *.part1.rar、*.part01.rar | part1 或 part01 那一片 |
| RAR3 | *.rar 加 *.r00、*.r01 | *.rar |
| Info-ZIP 跨卷 | *.z01、*.z02 加 *.zip | *.zip（排在最后一片） |

Info-ZIP 跨卷这一族能被识别与分组，但尚未完成解压验证，理由见 12.5 节。

## 17.4 刻意没有收进来的格式

解码核心其实还能打开更多的格式，但它们**没有可靠的特征值**，因此扫描阶段认不
出来，不会出现在结果列表里：

- 裸分区与卷：FAT、MBR、GPT、ext、HFS、APFS。这些格式的签名只有两个字节，而且
  位于文件的深处，收进来会把一大批不相干的文件误判成压缩包。
- 没有签名的编码：Base64、Intel HEX、裸 LZMA。
- 可执行文件：PE、ELF、Mach-O。
- 安装程序：NSIS。
- 媒体与复合文档：SWF、FLV、OLE 复合文档（扩展名为 doc、xls、msi 的那些）。

## 17.5 格式清单在设置页可查

设置页底部有一栏「支持的格式」，默认折叠，标题写着格式总数，展开后每种格式一张
卡片，列出它的识别依据与分卷命名，并标注解压一律走内置核心。

默认折叠是因为三十来种格式、每张卡片三四行，展开会把设置页的最后一屏撑得很长。
绝大多数时候只需要确认一眼「我这个格式在不在」。

# 第十八章 后台保活

## 18.1 为什么需要保活

解压一批压缩包可能持续几分钟到几十分钟。这段时间里如果用户切到别的应用、按下
电源键锁屏，Android 系统会倾向于回收后台应用以释放内存。一旦本软件被回收，
正在进行的解压就会中断。

因此解压开始后，本软件会启动一个前台服务，并发布一条带进度的通知。

## 18.2 通知栏上看到什么

通知栏会持续显示一条来自 DeepUnzip 的通知，内容是本批解压的进度。下拉通知栏
可以看到当前的处理状态。这条通知在前台服务运行期间不会被划走。

## 18.3 可以随时切走

因为解压跑在前台服务里，您可以随意切换应用、锁屏、接电话。回到本软件时进度
面板会接着显示，不会从头开始。

## 18.4 通知权限

Android 13 及以上系统需要通知权限才能显示这条进度通知。本软件会声明该权限并
在需要时申请。即使拒绝了通知权限，解压本身照常进行 —— 只是没有通知栏上的
可见进度。

## 18.5 与其它耗电优化的关系

部分厂商的系统设有额外的省电策略（例如在锁屏后一段时间内冻结后台服务）。本软件
使用前台服务属于系统认可的常规方式，绝大多数情况下不会被冻结。如果遇到解压
长时间停在同一个进度，可以检查系统的电池优化设置，把 DeepUnzip 加入白名单。

# 第十九章 隐私与权限

## 19.1 不联网

本软件的发布版本**不声明网络权限**。安装之后，在系统的应用信息页里查看权限列表，
看不到「拥有完全的网络访问权限」这一项。

这一条不是声明出来的说法，而是可以从安装包上直接核实的：应用清单里没有
INTERNET 权限，系统就不会给这个应用建立网络连接的能力。

与之配套的是：本软件不包含任何统计、崩溃上报或广告组件。这些组件通常都需要网络，
也通常都会收集信息。

## 19.2 不收集个人信息

本软件不收集任何个人信息，包括但不限于：设备标识、账号信息、使用行为、崩溃日志、
文件名、文件内容、目录路径。

需要联网才能完成的采集一概没有，本机范围内的采集也没有 —— 解压软件不需要知道
您是谁。

## 19.3 各种数据存在哪里

| 数据 | 存放位置 | 说明 |
| 设置项 | 应用私有目录 | 开关与数值，明文 |
| 密码库 | 系统加密存储 | 密文，密钥由系统密钥库保管 |
| 日志 | 应用私有目录 | JSON 文件，不含完整路径与密码 |
| 解压结果 | 用户指定或压缩包旁边 | 用户数据，卸载时不会删除 |

应用私有目录在卸载时会被系统一并清理。解压结果是用户数据，位于外部存储，卸载
不受影响。

## 19.4 申请的权限与用途

| 权限 | 用途 | 何时申请 |
| 所有文件访问 | 跨目录查找压缩包并写出结果 | 第一次点击「选择目标文件 / 文件夹」时 |
| 通知 | 显示解压进度通知 | 开始解压前 |
| 前台服务 | 保证长任务不被系统回收 | 随服务启动自动声明 |

在 Android 10 及更早的版本上，「所有文件访问」权限尚未存在，本软件改用读写外部
存储权限，用途相同。

## 19.5 权限申请的四条规矩

一、**隐私说明与权限申请分开**。本软件在首次启动时不会申请任何权限。

二、**用到时才申请**。存储权限在用户第一次点击选择目标时才发起，并且先说明用途。

三、**拒绝不惩罚**。拒绝授权后本软件不会退出，也不会循环弹窗，只是相关功能无法
使用，界面给出提示与再次申请的入口。

四、**不反复打扰**。权限被拒绝后，不会在短时间内重复弹出申请。

## 19.6 第三方组件

本软件使用了 7-Zip 的解码核心（LGPL-2.1 加 unRAR 限制）、LZFSE、ZSTD 与 XXH64
（BSD 许可），以及若干 Dart 与 Flutter 组件。

完整的许可声明与全文可以在「设置 → 关于 DeepUnzip」里读到。7-Zip 的源码快照
随本软件的项目仓库一同分发。

unRAR 部分只用于**解压** RAR 格式，不用于生成 RAR 压缩包 —— 这正是该许可明确
允许的用途。

## 17.6 格式之间的差别

三十二种格式不是同一种东西。从使用的角度，它们分为几类，各类的差别值得知道：

| 类别 | 代表格式 | 特点 |
| 带目录的归档 | ZIP、RAR、7-Zip、TAR | 可以随机取其中某个条目；多数支持加密 |
| 单文件压缩流 | GZIP、BZIP2、XZ、ZSTD、PPMd | 只压一个文件，没有目录结构 |
| 分卷归档 | RAR3、RAR5、Info-ZIP 跨卷 | 由多片拼成，缺一不可 |
| 打包格式 | CAB、LHA、ARJ、CPIO | 老式归档，通常不压缩或轻度压缩 |
| 软件包 | RPM、DEB、AR、XAR、CHM | 内部是归档加元数据 |
| 虚拟磁盘 | ISO、UDF、WIM、DMG、QCOW、VMDK | 单个文件里装着整个文件系统 |
| 磁盘镜像 | SquashFS、CramFS、VHD、VHDX | 同上，常见于嵌入式与虚拟化 |
| 专有归档 | Android Sparse、NTFS 卷 | 结构特殊，需专门处理 |

带目录的归档是最常用的一类。单文件压缩流在解压后只得到一个文件，因此输出目录
里只有那一个文件，形如 `x.gz` 解成 `x/x` 的目录结构不会出现 —— 它解出来直接就是
`x`。

## 17.7 只能列目录、不解数据的情况

有一类包打开之后可以列出里面的条目，但读取数据会失败。最常见的原因是**残缺的
分卷**：首卷的头部信息完好，所以条目表列得出来，但数据分散在缺失的后续分片里。

本软件在这类情况下会如实报错，而不是给出半份数据。判断的依据是：能列出条目
不等于能读出数据，两者是分开的两步。

## 18.6 通知栏上看不到进度

先确认通知权限是否已授予。Android 13 及以上系统需要单独申请通知权限，拒绝之后
解压照常进行，只是没有通知栏上的可见进度。

如果通知权限已授予却仍然看不到，检查系统设置里是否对本应用开启了「隐藏通知」
或在锁屏上隐藏通知内容。部分厂商的系统默认隐藏锁屏通知。

## 19.7 如何自行核实「不联网」

不联网这件事不需要相信任何声明，可以从安装包上直接核实：

一、在系统的「设置 → 应用 → DeepUnzip → 权限」里看权限列表，找不到「拥有完全
的网络访问权限」这一项。

二、导出应用清单查看权限声明，其中没有 `android.permission.INTERNET`。

三、在飞行模式下使用全部功能。扫描、解压、密码库、日志、设置不依赖网络，飞行
模式下完全可用。

第三条是最直接的验证方式。一个真正需要联网才能工作的功能，在飞行模式下必然
表现为某个按钮转圈或超时；本软件没有这样的功能，因为没有任何一个环节会去连网。
