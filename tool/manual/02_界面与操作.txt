# 第四章 界面总览

## 4.1 整体结构

本软件采用底部导航的页面结构，底部固定四颗标签，从上到下、从左到右分别是：

| 标签 | 页面 | 用途 |
| 解压 | 首页 | 选择目标、扫描、解压、查看本批结果 |
| 密码库 | 密码库页 | 增删密码，查看命中次数 |
| 日志 | 日志页 | 查看历史记录，按结果筛选，清空 |
| 设置 | 设置页 | 调整递归深度、输出方式、识别与错误处理等 |

四个页面都常驻在同一个容器中，切换标签不会重建页面，也不会打断正在进行的解压。
解压任务在后台独立运行，切到任何一个页面都可以，只是进度面板显示在首页。

首页和设置页的右上角都可能有入口跳转到独立的子页面：文件浏览器、关于页、许可
全文页。这些子页面用普通的路由跳转，按系统返回手势或左上角箭头返回。

## 4.2 页面布局通则

四个主页面共用同一套版式：

- 顶部是页面标题，下面一行小字是英文副标题或一句话说明。
- 中间是内容区，纵向排列若干张卡片。
- 底部留出约一百像素的空白，避免最后一张卡片被底部的导航栏压住。

卡片的视觉风格统一：深色半透明底、圆角、细边框，强调色为青、紫、橙、绿、红
五种，分别对应不同的语义。青色是常规强调，紫色用于密码与限额，橙色是需要注意、
但不算错误的情况，绿色表示成功，红色表示失败。

# 第五章 选择解压目标

## 5.1 入口

首页最上方那张卡片是唯一的入口，上面的文字是「选择目标文件 / 文件夹」，下面两行
小字是「选文件夹递归扫描 · 选单个文件只解它」与「自动识别加密 · 分卷 · 伪后缀」。

点击这张卡片会打开本软件自带的文件浏览器。这是本软件自己实现的页面，不使用系统
的文件选择器，原因见 5.5 节。

如果此前已经选过目标，这张卡片会换成一个「已选」卡片，显示目标名称与完整路径，
右侧有一颗「更换」按钮。点击「更换」回到浏览器。

## 5.2 选择文件夹

在文件浏览器中导航到目标文件夹，点击底部的「选择此文件夹」按钮（在只选中文件夹
的模式下也可以直接点击「当前目录」这一行）。

选定之后，本软件会递归扫描该文件夹下的全部内容 —— 包括子目录，逐层往下，直到
设定的递归深度上限。这是批量处理一整个目录时的用法。

## 5.3 选择单个文件

在文件浏览器中直接点击一个文件的名称，即以该文件为唯一目标。

此时只解这一个压缩包，同目录里其它没被选中的压缩包一概不动。首页的「已选」卡片
上显示的是这个文件的名字，下面一行是它所在的目录。

需要注意的是，选择了文件之后，输出位置的基准会退到该文件所在的目录。也就是说，
在默认输出模式下，解压结果落在那个目录旁边，与选择整个文件夹时的行为一致。

## 5.4 分卷压缩包的选择限制

如果点中的文件是分卷的第一片（形如 a.zip.001、b.part1.rar、c.r01），单文件模式
下是**无法**正确解开的 —— 因为其余的片不在选中的范围内。

本软件识别到这种情况时会给出提示，建议改用「选择文件夹」的方式选中整个目录，
让分卷的各片一起进入扫描范围。

## 5.5 为什么自建文件浏览器

系统提供的文件选择器在选中文件时，会先把整个文件复制一份到应用缓存目录，再把
缓存里的路径交给应用。对一个解压工具来说这是致命的：选中一个几 GB 的镜像文件，
会先白复制一份；而且返回的路径在缓存目录内，解压结果会写进应用缓存，用户既找
不到，系统也可能随时清理掉。

本软件在获得全部文件访问权限之后，可以直接读写真实路径，因此自己实现了一套
「列举目录、导航、返回选中路径」的浏览器，避免上述问题，也顺带让选择界面的风格
与全应用保持一致。

## 5.6 文件浏览器的操作

| 操作 | 结果 |
| 点击文件夹行 | 进入该文件夹 |
| 点击文件行 | 选中该文件（仅「选择目标」模式） |
| 点击顶部路径 | 复制当前路径 |
| 「上一级」 | 返回上一层；已在卷根时不可点 |
| 快捷位置 | 直接跳到当前卷的下载、文档等常用目录 |
| 「选择此文件夹」 | 以当前目录为目标返回 |
| 系统返回手势 | 逐级返回，退到卷根后再按才退出浏览器 |

顶部的路径栏用等宽字体显示，长路径会自动截断。退到卷根之后「上一级」按钮变为
灰色不可点 —— 再往上就是系统目录，对用户没有意义。

# 第六章 扫描结果

## 6.1 扫描过程

目标确定之后立即开始扫描。扫描是递归的：从选定位置出发，逐个目录往下走，读取
每个文件的开头若干字节，判断它是不是压缩包。

扫描期间首页显示一张「正在递归扫描」的卡片，上面有一个转动的指示器、已发现的
压缩包个数、当前正在检查的路径，以及一颗「取消扫描」按钮。

这里刻意**不显示百分比**。扫描是没有分母的 —— 目录里到底有几个压缩包，只有
扫完才知道。任何中间百分比都只能是编的，因此改用「已发现 N 个」这个真实的计数。

点击「取消扫描」会立即中止本次扫描，已经发现的结果保留。

## 6.2 扫描结果卡片

扫描结束后出现「扫描结果」卡片，右上角显示本批压缩包总数，中间是三个统计数字：

| 统计项 | 含义 |
| 总文件 | 本批扫描到的压缩包个数 |
| 需密码 | 其中扫描期就能判断出需要密码的个数 |
| 特殊格式 | 其中属于分片、伪后缀或嵌套包的个数 |

下面是一个可滚动的列表，每一行是一个压缩包，左侧的方块显示格式缩写，中间是
文件名与「大小 · 深度 N」，右侧是最多三个角标。

## 6.3 角标的含义

| 角标 | 含义 |
| 加密 | 这个包需要密码才能解开 |
| 分片 | 这是一个分卷压缩包，由多个文件组成 |
| 伪后缀 | 后缀名与文件头指示的真实格式不一致 |
| 嵌套 | 这个包是从上一层的压缩包里解出来的 |

一个压缩包可以同时带多个角标，比如一个加密的分卷包会同时显示「加密」和「分片」。

## 6.4 「深度」是什么

列表里每一行的第二行都写着「深度 N」。深度数的是**从被选目录往下走了几步**，
「一步」有两种，同等计入：

- 进入一层子目录；
- 解开一层嵌套包。

所以 `子目录/a.zip` 的深度是 1，顶层目录里的 `a.zip` 深度是 0，而 `a.zip` 里
解出来的 `b.zip` 深度也是 1。

这个数字与「最大递归深度」设置项用的是同一把尺子，见第八章。

## 6.5 被忽略的文件

扫描时有一批文件会被有意跳过，不列进结果：

- 后缀属于已知的容器格式，如 apk、docx、xlsx、pptx、epub、jar、war 等。这些
  文件内部虽然也是 ZIP 结构，但它们是有明确用途的文档或程序包，不是压缩包。
- 中心目录里显示出容器特征的文件。这一条是对上一条的补充：即使后缀被改成
  `.zip`，只要条目里出现 `[Content_Types].xml`、`word/`、`classes.dex` 这类
  标记，同样会被判定为容器格式并跳过。

被跳过的数量会记在扫描日志里，形如「忽略 3 个容器」。

> 「选择单个文件」模式下不受这条限制。明确点中的文件，即使它是 .docx，也会被
> 当作压缩包列入结果 —— 这是用户的明确意图，不应该被自动过滤掉。

## 6.6 结果列表的每一行长什么样

列表里每个条目占两行，外加右侧可能出现的角标。

第一行是文件名。文件名保持磁盘上的原样，软件**不会**因为识别出真实格式而改写它
—— 一个名叫 `报告.pdf` 的 ZIP，在列表里仍然叫 `报告.pdf`，只是右边多一个
「伪后缀」角标。改名会让用户对不上号。

第二行是「大小 · 深度 N」。大小是压缩包自身的体积，不是解开之后的大小；深度见
6.4 节。

角标一共有四种，可能同时出现：

| 角标 | 含义 |
| 加密 | 这个包需要密码 |
| 分片 | 这是一个分卷包，由多片组成 |
| 伪后缀 | 后缀与实际格式不符 |
| 嵌套 | 这个包是从别的包里解出来的 |

一个包可以同时是分片的、加密的、并且是从别的包里解出来的，三个角标就一起出现。

需要留意的是**分卷包在扫描阶段认不出「加密」**：判断一个包是否加密要读到它的头部
信息，而分片包的头在首卷里、信息可能不全。所以常见的情况是扫描时没有「加密」
角标，解压时却弹出密码框。这不是漏判，是信息在那个时刻还不具备。日志里会如实
记下密码的来源。

## 6.7 结果卡片上的三个计数

结果卡片下方有一行小字，形如「总文件 12 · 需密码 3 · 特殊格式 2」。三个数字的
算法是：

| 计数 | 算法 |
| 总文件 | 结果列表的行数；一个分卷包算一行，不是一片一行 |
| 需密码 | 列表里带「加密」角标的行数 |
| 特殊格式 | 列表里带「分片」或「伪后缀」角标的行数 |

一个包同时是分片和伪后缀时，在「特殊格式」里只算一次 —— 这个数回答的是「有
几个包需要额外留意」，而不是「出现过几个角标」。

「需密码」为 0 时确认卡片上不显示那一行，「特殊格式」为 0 时同理。少一行没有
信息量的数字，卡片更容易一眼看完。

## 6.8 扫描结果为空时

列表一个条目都没有时，结果卡片会显示空态而不是一片空白。可能的原因有四条，
按常见程度排列：

一、**目录里确实没有压缩包**。先确认选对了目录。

二、**文件都被当作容器格式跳过了**。扫描日志里会写「忽略 N 个容器」，N 大于 0
就属于这一种。见 6.5 节。

三、**存储权限没有授予**。此时扫描会给出提示，按提示重新授权即可。

四、**目录读不了**。系统的 `Android/data` 与 `Android/obb` 在部分厂商的系统上
即使持有全部权限也拒绝访问，这种情况界面会说明原因。

## 6.9 扫描进行中可以做什么

扫描是一个可以随时中止的过程。扫描面板上有「取消扫描」按钮，按下即中止本次
扫描，已经扫到的结果作废 —— 半份结果比没有结果更容易让人误判。

扫描期间可以自由切换底部标签：扫描跑在后台，切到密码库页加个密码再切回来，
扫描不会中断，计数也照常增长。

扫描期间主按钮显示「正在扫描…」并且不可点。这是有意的：扫描没结束时还不知道
要解的是什么，此时按下去没有明确的含义。

## 6.10 一批的边界在哪里

「一批」是本软件里一个反复出现的单位，它的边界是：

- **一次扫描的产出**构成一批；
- 解压以批推进，批结束时给出总结卡片，日志也按批记录；
- 重新选择目标会开始新的一批，旧的结果列表被清空。

一批内的包按扫描顺序处理，同一批共用一份设置快照 —— 也就是说，解压跑到一半时
去设置页改递归深度，这一批仍按开始时的值走，改动从下一批起生效。这条设计避免
了「同一批里的包被两套规则处理」这种难以复现的状态。

嵌套包属于它所来自的那一批，不单独成批，也不受「更换目标」的影响。
