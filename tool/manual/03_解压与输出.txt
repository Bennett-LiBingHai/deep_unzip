# 第七章 执行解压

## 7.1 主按钮的四种状态

首页最下方那颗大按钮，会随状态在四种文字之间切换。它不是四个按钮，是同一个按钮
承担了四件事，识别当前该按什么，只需看上面的字。

| 按钮文字 | 出现在 | 按下去做什么 |
| 开始解压 | 扫描完成、本批尚未跑过 | 先确认，再开始解压 |
| 正在扫描… | 扫描进行中 | 不可点，等扫描结束 |
| 停止解压 | 解压进行中 | 停下这一批，队列里剩下的丢弃 |
| 更换目标 | 本批已跑过 | 重新选择文件或文件夹 |

「更换目标」这一态容易被忽略，但很重要：一批扫描结果一旦解过，再点不会「重新
解一遍」，而是会往磁盘里再撒一套带 `_1`、`_2` 后缀的重复目录。所以按钮改成去干
真正有用的事 —— 换一个目标。

## 7.2 确认弹窗

点击「开始解压」之后，先弹出确认卡片，上面写着：

| 字段 | 内容 |
| 待解压 | 本批压缩包个数 |
| 需要密码 | 其中需要密码的个数（为 0 时不显示这一行） |
| 分片 | 其中是分卷的个数（为 0 时不显示这一行） |
| 输出到 | 解压结果落在哪里 |

之所以值得多这一道确认：解压会真的往磁盘写目录，而重名时不会覆盖，而是追加
`_1`、`_2`。也就是说点错一次不是「白点」，是留下一堆要人工清理的目录。

弹窗上有「取消」与「确认解压」两颗按钮。用手势把弹窗滑掉，等同于取消 —— 后面的
动作要写盘，手滑关掉不该等于同意。

## 7.3 解压过程中的显示

确认之后开始解压，首页出现「正在解压」面板，包含：

- 左上角的 LIVE 标记与标题，右上角的大号百分比。
- 一条进度条。
- 当前正在处理的条目名称。
- 四个指标：已完成、速度（MB/s）、递归层、剩余时间。

进度是**单调递增**的，不会往回退。原因是在无限制递归的情况下，一边解一边会发现
新的嵌套包，分母在过程中会变大。此时如果按原始比率显示，进度条会倒退，那比不
准确更让人困惑。因此进度只增不减，同时用「已完成」这个诚实的计数来补充说明。

## 7.4 停止

解压进行中，主按钮变成「停止解压」。按下之后当前这个压缩包随即中断，队列里剩下
的全部丢弃。

停止后首页出现总结卡片，标题是「已停止」，主按钮变成「更换目标」。已经解出来的
部分不会回滚 —— 它们是完整的。中断时正在写入的那个文件会被删除，不会留下一个
长度不完整的残件；这次解压新建、又什么都没留下的空目录也会一并收掉，不会在磁盘
上留一个空文件夹。（原本就存在的目录一个都不动。）

> 如果只是想跳过当前这个包、继续解后面的，不要按「停止解压」。那种情况请使用
> 错误弹窗上的「跳过」按钮，见第十三章。

**关于停止的延迟**：停止信号在解压核心的下一个进度点生效，正常情况下延迟在
零点几秒以内，与当前正在解的文件有多大没有关系。

## 7.5 本批结束

一批跑完之后首页出现总结卡片。卡片标题只有五种，由本批的真实结局决定：

| 标题 | 含义 | 颜色 |
| 全部解压完成 | 每一个包都成功解开 | 绿色 |
| 部分失败 | 有成功的，也有失败的 | 橙色 |
| 全部失败 | 每一个包都没解开 | 橙色 |
| 已停止 | 用户按了停止 | 橙色 |
| 解压出错，已停止 | 发生异常，流程中断 | 橙色 |

标题下方一行小字给出「共 N 个 · 成功 X · 失败 Y · 跳过 Z」的汇总。再下面是一颗
「打开输出目录」按钮，点击后请系统文件管理器跳到输出所在的位置。

> 只有「全部解压完成」配绿色勾选图标。其余四种一律用暖色与惊叹号圆圈 —— 绿色的
> 勾配「全部失败」是个自相矛盾的画面。

# 第八章 递归解压与深度

## 8.1 什么是递归解压

递归在本软件里有两层含义，两者都算：

一、**进入子目录**。选定一个文件夹后，不只看它自己，还往下逐层查找。

二、**解开嵌套包**。一个压缩包解开之后，如果在解出来的内容里又发现了压缩包，
就继续解下去。

这两种「往下走一步」是同等计入深度的。`子目录/a.zip` 比顶层目录里的 `a.zip`
多占一层预算，因为它自己已经走过一步了。

## 8.2 最大递归深度

「设置」页第一组里有一项「最大递归深度」，说明文字是「每进一层子目录、每解一层
嵌套包各算一层；0 表示不递归」。点击右侧的数值可以输入一个新值。

| 取值 | 效果 |
| 0 | 不递归。只处理选定目录下最外层的压缩包，不进子目录，不解嵌套 |
| 1 至 64 | 最多往下走这么多步 |
| 默认 | 20 |

取值范围是 0 到 64，超出范围时输入框会拦住，不会提交。

默认值取 20 而不是 0，是因为 20 在实际使用中等于「解到底」—— 真实的压缩包很少
嵌套到 20 层，所以默认行为是尽量解干净。

## 8.3 深度闸门对谁生效

**顶层的那批包也走同一道闸门**。这一点值得单独说明，因为它与直觉稍有出入：
深度为 0 时，不仅包**里面**的嵌套包不会解，**子目录里**的包也不会解 —— 因为按
8.1 节的规则，后者离被选目录更远，同样超出了一步的预算。

选定目录**自己**里面的压缩包不受影响，它们深度为 0，总是会被处理。

## 8.4 递归层数在哪里看

解压过程中，首页进度面板的四个指标里有一个是「递归层」。它显示的是当前正在处理
的这一步有多深，与 6.4 节的深度是同一个数。

# 第九章 输出位置

## 9.1 两种模式

本软件有两种输出位置模式，由「设置」页第一组里的「自定义输出目录」开关决定。

| 开关 | 模式 | 输出落在 |
| 关（默认） | 与源目录对称 | 每个压缩包各自旁边 |
| 开 | 镜像到指定根 | 用户每次选定的根目录下 |

## 9.2 默认模式：解到包旁边

这是默认行为，也是绝大多数情况下够用的行为。

规则很简单：压缩包在哪儿，解出来的目录就在它旁边，名字取压缩包的名字去掉压缩
后缀。

| 源 | 输出 |
| /sdcard/Download/a.zip | /sdcard/Download/a/ |
| /sdcard/Download/sub/b.7z | /sdcard/Download/sub/b/ |
| /sdcard/Download/c.tar.gz | /sdcard/Download/c/ |
| /sdcard/Download/d.zip.001 | /sdcard/Download/d/ |

因为每个压缩包都在自己的目录旁边展开，整棵结果树的形状与源目录树完全一致，所以
也叫「目录对称输出」。

后缀剥离会一路剥到没有压缩后缀为止：`c.tar.gz` 变成 `c` 而不是 `c.tar`。

## 9.3 自定义模式：镜像到指定根

打开「自定义输出目录」之后，每次点击「开始解压」时会先弹出文件浏览器，让您选择
一个根目录。选择完成后才出现确认弹窗 —— 顺序不能反过来，因为确认弹窗上「输出到」
那一行必须是真实的，否则用户是在一个还不知道往哪写的界面上点确认。

选定根目录后，输出按**源目录的相对结构**镜像进去：

| 源 | 输出根 | 结果 |
| /src/a.zip | /out | /out/a/ |
| /src/sub/b.zip | /out | /out/sub/b/ |
| /src/x/y/c.zip | /out | /out/x/y/c/ |

也就是说，从被选目录往下的目录层级会被原样复制到输出根下面。这样即便一次解了
几十个包、分布在不同层级的子目录里，结果的组织方式依然一目了然。

如果中途取消了选目录这一步，本批不会执行，界面会给出「未选择输出目录，本批未
执行」的提示。**这一步取消是会出声的**，因为它与「主动去选、取消就取消」不同：
这里是用户按了开始解压、被弹了选择、然后退出来，一声不吭会让人以为按钮坏了。

## 9.4 嵌套包在自定义模式下的位置

嵌套包不需要单独指定输出位置。父包的输出目录本身已经落在了镜像位置上，而从父包
里解出来的嵌套包，就在那个目录里面被发现的，于是它的输出自然落在父包输出目录的
旁边 —— 也就是镜像位置的下一层。

最终结果仍然是一棵与源目录同构的树。

## 9.5 重名怎么办

如果目标目录已经存在，本软件**不会覆盖**，而是给新目录追加 `_1`、`_2`、`_3`
这样的后缀，直到找到一个不冲突的名字。

这是有意选择的行为：解压往往是一批一批做的，覆盖意味着前一批的结果被悄悄抹掉。
追加后缀的代价是可能需要人工清理，但不会有数据被无声销毁。

## 9.6 打开输出目录

本批结束后的总结卡片上有一颗「打开输出目录」按钮。它打开哪个目录取决于当前的
输出模式：

- 默认模式：打开被选的目标目录。因为输出是每个包各自同级的，没有单一的「输出
  根」，但整棵树都在源目录底下。
- 自定义模式：打开您选定的输出根。此时源目录那边什么都没有，打开源目录只会让
  人对着空目录找半天。

「打开目录」依赖系统文件管理器的能力。部分厂商的系统不支持直接跳转到指定目录，
此时本软件会如实提示「文件管理器已打开，但无法定位到目录」，并把完整路径显示
出来供复制。

## 9.7 一个完整的输出例子

假设被选中的目录是 `/sdcard/Download/duz_demo`，里面有这样的结构：

```
duz_demo/
  a.zip
  b.tar.gz
  sub/
    c.7z
    d.zip
```

默认模式（解到包旁边）解完之后的磁盘结构是：

```
duz_demo/
  a.zip
  a/
  b.tar.gz
  b/
  sub/
    c.7z
    c/
    d.zip
    d/
```

注意三点：压缩包本身**原样保留**，不会被删掉或改名；`b.tar.gz` 解出的目录叫 `b`
而不是 `b.tar`；每个解出来的目录都与它的包同级，所以整棵树的形状没变。

自定义模式（镜像到输出根 `/sdcard/Download/duz_out`）解完之后：

```
duz_out/
  a/
  sub/
    c/
    d/
```

这一次源目录里除了压缩包什么都没多出来，结果全部落在输出根下面，并且保留了
`sub/` 这一层。

## 9.8 条目名的处理

压缩包内部的条目名不总是规规矩矩的。本软件在落盘之前会对每个条目名做一遍清洗：

- 反斜杠换成斜杠，兼容在 Windows 上打包的压缩包。
- 去掉开头的斜杠与盘符，拒绝 UNC 路径。
- 合并连续的分隔符，去掉空段与 `.` 段。
- 拒绝 `..` 段 —— 这是防止「路径穿越」的关键一步，凡是试图写到输出目录之外的
  条目都会被拒绝。
- 单段超过 255 字节的会被截断。

清洗之后还会再做一次核对：这个条目最终要写到的位置，必须位于输出目录之内。
两道检查都通过才会写盘。被拒绝的条目不会静默消失，会记入日志。

## 9.9 输出到外置存储卡

被选目录位于可移动存储卡（例如 `/storage/XXXX-XXXX/...`）时，输出也落在同一张
卡上，与内置存储的做法完全一致。

需要留意的是剩余空间是按**目标卷**判定的，不是按设备总剩余空间。手机内置存储
还剩很多，不代表存储卡上还装得下 —— 判据用的是输出目录所在的那一卷。

## 9.10 解压过程中界面上能做什么

解压是后台任务，过程中可以做这些事：

- 切换到底部任意标签页，进度不受影响。
- 下拉通知栏，看到带进度的常驻通知。
- 锁屏、切到别的应用、接电话。

不能做的事只有一件：更换目标。目标卡片上的「更换」在解压期间不可点，因为换
目标会让界面显示的目录与实际在解的目录不一致。要换，先按「停止解压」。

## 8.5 深度用完了会怎样

嵌套层数达到「最大递归深度」时，本软件不会报错，而是把这一条记为**跳过**（不是
失败），日志标记写明是深度限制。原因是在最外层包里发现一个新包、又暂时不解它，
是符合预期的正常行为，不是错误。

想解开那个被跳过的包，有两种办法：把最大递归深度调大，或者直接把它所在的目录
当成新的目标重新扫描一次。
